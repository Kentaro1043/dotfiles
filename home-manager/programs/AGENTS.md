# エージェント向け規約

## Git 操作

### ブランチ

ブランチ名について、作業環境によっては自動生成によるランダムな単語になっている場合があります。

この場合、 `codex` prefix 付きの、作業内容に応じた適切なブランチ名へリネームしてください。

### Git Commit

Commit 指示は、以下の3通りからいずれかを行います。

- Commit,Push しない
- Commit のみを行い、 Push はしない(デフォルト)
- yeet スキルを用いてPRを作成する

Git Commit を行う場合は、Conventional Commits 規約と Gitmoji を使用し、コミットメッセージは日本語で書いてください。
例を以下に示します。

> feat: ✨ 新規機能を実装

作業の規模が大きいときは、適切な機能単位で Commit を行ってください。

### Pull Request

Pull Request 作成時は、 yeet スキルを使用してください。
title と description は日本語で書いてください。
また、です・ます調ではなくだ・である調で書き、体言止めを適切に使用して端的さを保ってください。
ただし、 yeet スキルの説明にある Why や What Changed などの見出しは英語のままにしてください。

ブランチ名と作業内容が合っていない場合は、作成前にリネームしてください。

## コード品質

### コードコメント

長すぎるコメントは避けてください。

複数行に渡って日本語の文章を書くのではなく、基本的には1~2行の説明を書く程度にしてください。

ただし重要情報や、必要なコマンド、生成などに使用したコマンドのログがある場合はその限りでありません。

動作元PCに依存したコメントは、コード共有前に削除する必要が生じるため書かないでください。

### フォーマッタ・リンタ

各言語について業界標準のフォーマッタ・リンタを使用し、コード品質を保ってください。

## 日本語

記事、ドキュメント、PR の説明文、コミットメッセージなどの日本語の文章を書いたり直したりするときは、常に yomiyasu:yomiyasu スキルで推敲してください。コードを直したあとの作業の報告には使わなくてかまいません。
